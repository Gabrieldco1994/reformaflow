## Architecture

- Turbo monorepo: `apps/web` is Next.js 14 App Router (port 3000), `apps/api` is modular NestJS (port 3001), and `packages/domain` holds shared enums, pure rules, authorization maps, and calculations.
- Browser requests use `apps/web/src/lib/api.ts` with cookie credentials. Nest applies global JWT, role, module, and project-access guards before Prisma reaches SQLite.
- Import domain code only through `@reformaflow/domain`; rebuild it after changes because both apps consume its generated output.
- PESSOAL is the cross-project financial cockpit. Account/card imports, expenses, receipts, settlements, allocations, and mirrors feed monthly/account views; their contracts live in `docs/`.
- Maria uses Gemini for agent/classification flows and VibeVoice on Modal for TTS. Static uploads are served from `uploads/` at `/uploads/`.

## Project-type gates

- `PROJECT_FEATURES` controls product capability, `TYPE_MODULES` controls authorization, and `PROJECT_NAV` controls rendered navigation. They are distinct sources in `packages/domain/src/config`; never replace them with hard-coded project-type checks.
- `expenses` capability is intentionally retained for CASA/CARRO while their `/expenses` navigation redirects to the Avulsas tab in `/bills`.
- `carInfo` is a CARRO-only 1:1 resource, not a feature flag; its API uses `PUT` with Prisma `upsert`.
- Authorization reconciliation must remain in both `AuthService.buildPublicUser` and `JwtStrategy.validate`, using union semantics. All three grant columns (`allowedProjects`, `allowedModules`, `allowedProjectTypes`) share one fail-closed parser, `parseGrantJson` in `apps/api/src/auth/grant-json.ts`: missing/blank/malformed JSON, a non-array, or an array with no string values all fail the whole read closed (401) instead of degrading to `[]` (read downstream as "no restriction"). `AuthService.updateSelfObjectives` reuses the same parser inside its own transaction — see the self-authorization rule in `docs/saas-onboarding.md`.
- `MonthlyOverviewController` binds its project param as `:pessoalProjectId`, not `:projectId` — deliberately. `ProjectAccessGuard` only recognizes literal `projectId`/`sourceProjectId`/`targetProjectId` param/query/body keys; keeping `:projectId` would let that guard short-circuit with a blanket 403 (or silently allow) before `MonthlyOverviewService.resolveAnchor`/`resolveHub` ever runs, which is what has to own the 404 (missing/deleted/cross-tenant) vs 403 (out-of-scope) vs 400 (authorized but not PESSOAL) distinction. Do not rename it back to `projectId`. Because that guard is bypassed, EVERY handler on this route must itself pass the full `MonthlyOverviewRequester` into service-level anchor resolution (`ensurePessoalProject`/`resolveAnchor`/`resolveHub`) — passing only `requester.id` (e.g. for audit) is not enough.

## Data and test safety

- Never run `prisma migrate reset`, `db push --force-reset`, delete `prisma/dev.db`, or run tests against it; it contains real data.
- Before schema migrations, back up `prisma/dev.db`, then run `cd apps/api && npx prisma migrate dev --name <desc> --schema=../../prisma/schema.prisma`. A migration that will reach a persisted schema also needs an upgrade fixture built from a sanitized backup, or a structurally equivalent legacy fixture; passing only against a fresh database is not release evidence.
- During recovery from a failed production migration, keep the temporary entrypoint that skips migrations until the legacy-data repair has a reviewed dry-run manifest and restorable backup, the failed migration state has been resolved, and `prisma migrate deploy` has succeeded. Quiesce the API with no writers from the final dry-run through normalize, resolve, and migrate. The repair manifest is confidential mode `0600`: it contains row IDs and scope keys, and must never be attached or published; only a public summary with counts and a truncated hash is shareable. Only after migration succeeds may SRE clear the machine's emergency `init.entrypoint`/`init.cmd` override so the Dockerfile `CMD` restores the normal migrate-first entrypoint. Never add `[processes] app="/entrypoint.sh"`; `http_service.processes = ["app"]` is sufficient.
- The production image does not contain `scripts/` or `deploy/`. For an authorized migration recovery, extract `deploy/quiesce/watchdog.sh` and `deploy/quiesce/op-wrap.sh` from the tested PR HEAD, transfer them to a unique persistent volume directory like `/data/quiesce-<RECOVERY_RUN>`, and local↔remote SHA-256 checksum each. Only with both matching, arm the machine with `--skip-health-checks` and `init.cmd = ["sh","${QUIESCE_DIR}/watchdog.sh"]`. After machine update completes, transfer `scripts/normalize-external-id-duplicates.mjs` to `/app/normalize-external-id-duplicates.mjs`, checksum it remotely, and only then run `op-wrap dryrun`. Never copy the repository or install dependencies; `createRequire` resolves the existing `/app/node_modules/@prisma/client`. **All machine access goes through `op-wrap` (`dryrun` / `apply` / `disarm` / `status`) run via the persistent directory path — never a raw `node .../normalize-external-id-duplicates.mjs` and never a manual `sqlite3`/`prisma studio`.** The manifest path is chosen by `op-wrap` under `$QUIESCE_DIR` (a timestamped unique directory per recovery attempt, e.g. `/data/quiesce-<RECOVERY_RUN>`); the supervised chain publishes `$QUIESCE_DIR/manifest.current` **only after the normalizer exits 0** (fail-closed — a failed/killed normalizer leaves no new pointer). There is no `/tmp` manifest protocol. `apply` and every download/cleanup read the path from `$QUIESCE_DIR/manifest.current`. After preserving evidence and the local `0600` copy, remove the scripts from the persistent volume, the normalizer from `/app`, the manifest and `$QUIESCE_DIR` from the machine (exact paths, no wildcard, tolerating missing files) when recovery ends.
- Every test runner or standalone Prisma test must load `scripts/test-db-env.cjs`; intentional dev scripts and Playwright against a running API are exceptions.
- Prisma soft-delete behavior lives in `apps/api/src/prisma/prisma.service.ts`. Add models without `deletedAt` to `modelsWithoutSoftDelete` in the same change. **`$use` runs inside `$transaction` too — the old "`$transaction` bypasses `$use`" claim was false and caused a real incident (#586, see Scars).** What actually determines whether a query sees soft-deleted rows is the **action**, not the transaction: the middleware only intercepts `findMany`, `findFirst`, `delete`, `deleteMany` (injecting `deletedAt: null` when the caller didn't specify it) — `findUnique` is never intercepted, in or out of a tx, and returns soft-deleted rows as-is. To make a `findFirst`/`findMany` see a soft-deleted row, pass `deletedAt` explicitly in `where` — but the idiom changes the result set: `{ not: null }` returns ONLY deleted rows, while `{ not: undefined }` returns BOTH live and deleted rows (any value, including `null`, satisfies "not undefined"). That second idiom is exactly what the exported constant `INCLUDE_SOFT_DELETED = { not: undefined }` (`apps/api/src/prisma/prisma.service.ts`) encodes, used by `FinancingService.upsert()` to reactivate a soft-deleted `Financing`/`FinancingInstallment` (#586) — don't "simplify" a query using it back to `{ not: null }` or drop the key, that silently turns reactivate-or-create into deleted-only-or-create. For a single row by unique key, `findUnique` always sees soft-deleted rows regardless of idiom.
- Cross-project rateio allocations must sum to the source `valorTotal`. PESSOAL movements without card/account belong to Carteira and must remain visible in account views and totals.
- In PESSOAL account views, count a rateio source exactly once, preserve its Carteira/account/card origin, and exclude every paid target from `saidas`/`saiuMes` by enumerating tenant-scoped `RateioAllocation`.
- `Expense.linkedExpenseId` reflects only the **first** target of a rateio (legacy 1:1 field); it is not the full allocation set. `GET :id/rateio` may receive a source or target id: resolve the canonical `sourceExpenseId` through tenant-scoped `RateioAllocation` (never through `linkedExpenseId`), then require ACL access to **every** participant.
- `GET :id/rateio` is **source-only** (#448 B1b, shipped): unless the requester can see every active participant AND the enumerated allocations sum exactly to the source `valorTotal`, respond with the payload of a purchase that was **never** rateada — anchored on the id that was asked for, never on the resolved source. There is no partial list, no `hidden*` field, and no number a partial list could be subtracted from. A redacted response must stay byte-identical to a never-rateada one: any new field breaks that indistinguishability. Lock: `apps/api/src/expense/expense.rateio-redaction.spec.ts`.
- Legacy `last4` identity is fail-loud, never fail-silent: when `payInvoice`/`undoInvoicePayment` resolve a card/account by `last4` alone and more than one active row matches, respond **409** (`resolveUniqueLegacyMatch`, `apps/api/src/common/invoice-identity.ts`) instead of picking one. Prefer explicit `cardId`/`accountId`; settlement is never resolved by `tenantId+last4` alone.
- The view side of that contract is **not optional and not implicit**: a surface that renders an invoice CTA must consume the server's `actions` array and never synthesize its own verb. The server already answers `actions: []` for an ambiguous `last4`; a client that ignores the field renders a button whose only outcome is a 409 the user cannot act on. Shipping the server half without the client half turns "fail loud" into "dead end" — pair them in the same release.
- Merchant-category rules are tenant-scoped and change category only, never value or cash; readers and writers must pass `tenantId`.

## Code and UI conventions

- Keep route pages thin; place route-local components, hooks, types, and helpers in `_components`, `_hooks`, `_types.ts`, and `_lib`.
- Call `useProject()` only inside React components/hooks. Reuse `apps/web/src/lib/api.ts`, `apps/web/src/lib/expense-options.ts`, and domain exports instead of parallel helpers.
- Freeze the clock in current-month tests (`vi.setSystemTime` or `page.clock.setFixedTime` before navigation) and validate date-sensitive suites with `TZ=UTC`.
- Route, auth/onboarding, and access-gate changes require Playwright because jsdom does not exercise redirects or middleware; reproduce parallel-only failures with `--workers=1`.
- Removing a slug from `PROJECT_NAV` is repo-wide, never local: gates derived from nav live far from the config — the mobile dock's 4th slot (`canViewCards`), `MaisSheet` group membership, and `getProjectHomePath` all read it. Run the **whole** `apps/web` vitest suite before pushing; a targeted selection passes and CI does not (2026-08-21, PR #528: four slugs removed, seven suites red, one of them a real regression — the dock silently dropped from four destinations to three).
- When a nav/config removal breaks a test, re-point the fixture, don't rewrite the expectation to whatever the code now returns. The property under test usually still matters; only the slug it was written against died. Rewriting the expectation leaves a green test that proves nothing.
- Update `docs/manual-do-aplicativo.md` in the same change when visible behavior changes.
- In a Nest controller mixing literal and `:id` routes, declare literal
  segments (e.g. `@Get('paid-origins')`) BEFORE the `@Get(':id')` handler —
  otherwise the parameterized route swallows the literal one as an id.
- UI changes require runtime QA at 375/390px and desktop. Use `MovimentacaoRow` as the financial-list layout; keep touch targets at least 44px and monetary values `nowrap`.
- Mobile means the responsive/PWA experience in `apps/web`, never a native iOS/Android app.
- Maria tool money values stay strings until `parseSpokenMoney`; schedule ordering goes through `sortScheduleByDate`.

## Collaboration

- Work in an isolated git worktree, branched from `origin/main`. Never edit/reset the shared checkout or use `git stash`, which is shared across worktrees. The shared checkout can sit many commits behind `origin/main`, and an agent auto-loads this file from the tree it runs in — so a stale checkout silently hands it an outdated contract.
- Two worktree traps that fail silently, both costing a full verification cycle (2026-08-21): rebuilding `packages/domain` without `rm -rf dist *.tsbuildinfo` first, where an inherited `tsbuildinfo` makes `tsc` exit 0 while `dist/types/` is never emitted; and `ln -sfn <target> <dir>` against a directory that already exists, which creates the link *inside* it instead of replacing it — `apps/web/node_modules` reappears on its own because vitest writes `.vite` there. Both produce a clean typecheck against the wrong tree.
- Never remove `apps/web/src/app/prototype/agent-monitor/` or `tools/agent-monitor/`; both are production functionality.
- For multi-agent coordination, use `.claude/agents/fleet-po.md`. One owner per branch; the PO owns merge order.
- Experience owners decide Web, Mobile/PWA, or Maria contracts; the existing backend/frontend builders continue to implement them.
- Open PRs against `main`, verify `baseRefName=main`, and require `gh pr checks <n>` to be green before merging.
- A deploy concurrency lock prevents overlap, not stale ordering. Keep `cancel-in-progress: false`; inside the lock, compare the run's full SHA with the current full SHA of `main` immediately before publishing and again after checks/smokes, failing either stale gate. Release proof requires exactly one Fly machine `started`, its sole check passing, `image_ref.labels.GH_SHA == GITHUB_SHA`, latest release `complete`, release `ImageRef` equal to `machine.config.image` after stripping its `@digest`, `/api/docs-json` 200, and `/auth/me` 401. Do not add `/health` or a SHA build arg.
- AI commits must include the agent's own `Co-authored-by` trailer.

## Scars — rules paid for with an incident

Each line is a real failure, with its date and what it actually cost. Delete one only when you can show the failure is now structurally impossible.

- **A green deploy can still leave old code stopped or the API down** (2026-08-28, #629). An older run finished after a newer one and overwrote `main` because the concurrency lock serialized work but did not reject a stale SHA; another green deploy accepted a Fly machine in `stopped`; and #570's migration passed on a fresh database but failed on legacy rows, leaving the migrate-first entrypoint unable to start the API for about 35 hours. The controls are paired: a full-SHA stale gate inside the lock immediately before deploy; post-deploy proof of a `started` machine, health, and the expected full SHA; and migration tests against a sanitized backup/legacy upgrade fixture. During recovery, never restore the migrate-first entrypoint until the failed migration is repaired, resolved, and successfully deployed.
- **A dead screen does not imply a dead service** (2026-08-19). `/financeiro` was unreachable for 200 of 200 users, so an agent retiring it also deleted 146 lines from `agent-tools.service.ts` — silently removing six *live* Maria tools. Maria never went through the screen's permission; her gate is `financialScope()`. Before removing any service code behind a dead surface, enumerate the callers, not the routes. Retire HTTP and screens; never the calculation.
- **A barrier test must not derive its expectation from the constant it protects** (2026-08-19). The first guard against that deletion read the same list the next remover would edit, so it would have gone green while the capability vanished. Pin the expected set literally.
- **A PR must not edit the contract it has to satisfy** (2026-08-19). A change deleted the `AGENTS.md` line stating the rateio contract and replaced it with wording that legalized the very leak it was supposed to close. Contract edits ship in their own commit, reviewed against the code, never inside the feature that must obey them.
- **Before changing a field, read the docstring of its type** (2026-08-19). `rateio.types.ts:52-57` carried an explicit warning that "fixing" `rateadoCents` to Σ visible items would reopen a known leak. The change was made anyway, and the review (mine included) never opened that file. The invariant was written where it belonged; nobody looked.
- **A partial list plus a total is a leak by subtraction** (2026-08-19). Redacting items while keeping a total-aware sum let any reader compute the hidden amount exactly, because the server refuses writes unless allocations sum to `valorTotal`. Redaction is only safe when the response carries no derivable remainder — hence source-only.
- **Two different databases are both named `dev.db`** (2026-08-20). Local is `prisma/dev.db`; production is the Fly volume at `/data/dev.db` (`apps/api/fly.toml`). Measuring the local file and reporting it as production happened twice in one day, to two different actors: it produced a false "zero usage" reading that nearly justified deleting a live feature, and a "2 admins affected" blast radius that was really 3 in production. Any claim about production data is measured with `fly ssh console -a reformaflow-api -C "sqlite3 -readonly /data/dev.db '<sql>'"` (tables are snake_case) and says so; a reading of `prisma/dev.db` is labelled local. Briefs that ask an agent for production numbers must carry this distinction — the agent cannot infer it.
- **Review both halves of a PR whose title says "and"** (2026-08-20). #499 shipped "409 on ambiguous `last4` **and** all-or-nothing rateio". Only the rateio half was reviewed; the `last4` half reached production without its web counterpart, leaving a real tenant with two cards ending `1234` facing a CTA that could only 409. When a PR carries two changes, ask of each: does this half have a counterpart that is not merged yet?
- **A count is not a fact until the disqualifying column is in the query** (2026-08-21). Four wrong numbers were reported to the PO in one session, each one column or one join away from correct: "7 real users have `expenses` without `monthlyOverview`" was **0** once joined against `projects` and `user_activity_logs` (six tenants owned no project; the seventh had never logged in); "4 broken onboarding steps" was **2** once `journey_steps.enabled` was read; "one dirty worktree" was **two** once the nested `*.worktrees/` level was walked; "#530 is waiting for your merge" had merged an hour earlier. None was a hard query — each was the query stopped one column early. The control: **publish the command next to the number.** Any count offered as a business fact carries the exact query that produced it and names the columns that would disqualify a row — `deleted_at`, `enabled`, `is_guest`, activity count, and the join proving the row is inside the scope being claimed. A number without its command is an estimate and is labelled as one.
- **A decision is not implemented until a named owner has it** (2026-08-21). The PO decided to remove the "case 3" permission branch (#529). The decision was recorded in the tracker, communicated back, and briefed into two agents *as context* — but nobody was ever assigned the four-line change, so `feat/u4-hub-nav` kept carrying the opposite of the decision while everyone treated it as settled. The `issue-maintainer` caught it by reading the code, not the plan. Announce a product decision and its owner in the same message, with the file list; a decision with no owner is a rumour.
- **A message to a running agent is queued, not delivered** (2026-08-21). "Stop, that approach is dead" reached `fe-u4-e2e` only when its turn ended; by then it had committed three commits of the invalidated approach. The runtime's `Message delivered` means *enqueued*, not *read*. Dispatched work cannot be cancelled — so an expensive approach is approved **with a stop point inside it** ("report the plan before implementing"), never approved wholesale on the assumption it can be interrupted later.
- **`.claude/` is tracked repo content; only `.claude/worktrees/` is scratch** (2026-08-21). While closing the `npm run format` hazard I recommended — and briefed into an issue — adding `.claude/` to `.gitignore`. `git ls-files .claude` returns **43 tracked files**: the whole agent roster and the skills. A blanket ignore hides the roster from every future contributor, and a stray `rm -rf .claude` deletes it (I did exactly that in a worktree and had to `git checkout` it back within the minute). Scratch lives in `.claude/worktrees/` (0 tracked) and `.agents/` (0 tracked); scope every ignore, delete and glob to those two, never to the parent.
- **`git add -A` commits the working tree, not your change** (2026-08-24). A one-line `.gitignore` fix shipped as a 26-file commit because the agent's tree still had another issue applied; the PR read as "it's just a gitignore" and carried stale copies of three files another PR was editing. Every brief says `git fetch origin` before `worktree add`, `git add <path>` explicitly, and `git show --stat` as proof of scope before pushing.
- **Grepping the working tree answers about `main`, not about the branch** (2026-08-24). Twice in one day a Fleet PO declared code dead after grepping the shared checkout — once calling a live CSS class unused, once (me) missing a design system because I searched `skin-minimal` when the attribute is `data-ui-skin="minimal"`, applied to every project. To verify a branch use `git grep <pattern> origin/<branch> -- <path>`; to verify an attribute, grep the value, not the name you assume.
- **A gate whose fixture is all zeros is blind** (2026-08-24). The KPI overflow guard (#578) passed because every value in the mock was `R$ 0,00` — 7 characters fit any width — and #588 shipped a money value broken across two lines with an orphan `-`. A layout gate needs the longest realistic value (6 digits, negative) at the narrowest supported width, with the side panel open.
- **A test that reimplements the code under test proves nothing** (2026-08-24). PR #598 shipped a `page.filters.test.tsx` that copied the page's `useState` into the test file and asserted on the copy: reintroducing the bug in `page.tsx` left it green. Same PR asserted `classList` contains `min-h-11` instead of measuring the box. Render the real unit, assert behaviour, and **validate by mutation** — reintroduce the defect and confirm red before opening the PR.
- **A false doctrine, copied into four normative files, produced one coordinated wrong design** (2026-08-25). "`$transaction` bypasses `$use`" was stated as fact in `AGENTS.md`, `architect.md`, `backend-expert.md` and `qa-engineer.md`. It is false: the middleware in `prisma.service.ts` intercepts by **action** (`findMany`/`findFirst`/`delete`/`deleteMany`), not by transaction context — `findUnique` is the one that's never intercepted, tx or not. #616 (fixed #586's soft-delete-then-recreate 500) was designed and reviewed by agents who all read the same false claim, so the fix widened `findFirst` queries expecting the tx to make them see soft-deleted rows — it didn't, the middleware re-injected `deletedAt: null` regardless, and the exact original 500 still happened after merge, on the real app, with 25/25 e2e green. The e2e passed because it instantiated `new PrismaClient()` directly instead of the real `PrismaService`, so it never ran the `$use` middleware it was supposed to be testing against (see the sibling scar about e2e tests blind to this middleware). Caught only by driving the actual UI against a real `PrismaService` — no unit test, no mocked-Prisma e2e, and no code review of the merged diff surfaced it. A normative claim about framework behavior is verified by running it, not by how many files agree with it.
- **`$queryRaw`'s `COUNT(*)` is a `bigint`, not a `number` — a `=== n` comparison against it is always `false` and reads as a passing negative** (2026-08-25). While verifying this very doctrine fix by execution, a probe compared a `$queryRaw`-returned count with `=== 1` and got a false negative that looked like `delete()` was doing a hard delete — nearly contradicting the PR it was meant to confirm. It was caught only because two probes (on `Project` and `Reminder`) disagreed with each other and the mismatch triggered distrust of the instrument before any conclusion was drawn; if both had "failed" the same way, the wrong finding would have shipped. Call `Number(row.c)` (or equivalent) before comparing a raw-SQL count to a number. Prisma's typed `model.count()` returns a real `number` and is unaffected — the trap is specific to `$queryRaw`/`$queryRawUnsafe`.
- **A live screen is not implied by live code** (2026-08-24). #529 collapsed navigation without deleting the screens, so issues opened from real runtime measurements now name components nothing renders. An agent "fixed" `PersonalExpenseCard`'s touch target and wrote an e2e that navigated to `/conta` — which does not mount it — and silently measured a different component's button with the same `title`. Before fixing any UI defect, prove the chain: route in `PROJECT_NAV` → render condition → component. If a link is missing, the issue is a closure, not a fix.
- **The shared checkout's history is disjoint from `origin/main`** (2026-08-24). `git merge-base origin/main main` in `~/reformaflow` returns nothing: 753 commits with no common ancestor, because the project squash-merges. Work committed there never reaches `main` by rebase or merge — a commit of 157 files sat unreachable until it was recovered by reflog. Treat `~/reformaflow` as read-only and branch every worktree from `origin/main`.
- **A production quiesce window must self-heal machine-side, never depend on the operator process** (2026-08-28, #629). The migration-recovery window used to be "an operator holds the API quiesced by hand"; if every `flyctl ssh` connection died, nothing brought the API back. The fail-safe is `deploy/quiesce/watchdog.sh` running as the Fly machine command: a written-once absolute deadline on the volume (a restart re-reads it, never renews it; a restart with a free lock collapses the window immediately), the operator chain run under a supervisor that lives outside the chain's process group and holds one `flock` lock for the chain's whole lifetime, known-group `TERM`→grace→`KILL` teardown of only the pgid it created (reaping reparented orphans GNU `timeout` abandons), and Node-direct started only after acquiring that same lock. Nothing else is ever signalled and there is no "cancel a running chain" verb — `timeout` inside the supervisor is the only automatic cancellation; `op-wrap disarm` just requests the Node-direct restore once the lock is free. `caffeinate` (or any operator-side keep-alive) is secondary comfort, never the mechanism. No manual `sqlite3`/`node`/`prisma studio` on the machine during a window: the lock only protects the supervised chain and Node-direct; every DB touch goes through `op-wrap`.
- **Defence in depth means the service filters, not just the guard** (2026-08-24). `CarInfoService` took `tenantId` and never used it (#498); `MerchantClassifierService.removeManual` still passes it to a top-level `deleteMany` where a missing value makes Prisma drop the filter and delete every tenant's rows. Both were safe only while one guard held. A service that receives `tenantId` must filter by it, so the next caller — a job, a command, a new controller — cannot bypass the boundary.
